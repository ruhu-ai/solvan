# Incident console review checklist

Use this checklist when changing incident list, incident detail, evidence,
actions, verification, or Reliability Case surfaces.

- [ ] User impact is visible before infrastructure detail.
- [ ] Observed facts, inferred hypotheses, proposed actions, and verified
      outcomes are visually and semantically distinct.
- [ ] Every important claim has a resolvable evidence reference, freshness, and
      classification scope.
- [ ] The current owner, lease, next action, and human decision are explicit.
- [ ] Proposed, authorized, reconciled, and independently verified are not
      collapsed into one status.
- [ ] A warning names the safe next step and owner; it does not imply that a
      blocked action is available.
- [ ] No screen offers “mark healthy,” “mark verified,” or equivalent authority
      without the corresponding deterministic receipt.
- [ ] Approval shows exact target, environment, digest, version, risk, expiry,
      policy, and rollback context.
- [ ] Mobile and keyboard flows preserve safety-critical context.
- [ ] Dynamic status messages are accessible without taking focus.
