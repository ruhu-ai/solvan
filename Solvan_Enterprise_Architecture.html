Architecture Principles And Invariants

These are not aspirations: each principle is enforced by code, schema, or a required test, and changing one requires changing the governing specification. They bind every section that follows.

P1 · Two planes, one authority

Gemini may investigate, rank hypotheses, plan, summarize, and draft. Typed application services own permissions, state transitions, risk, action budgets, approval validity, target reservations, idempotency, and mutations. Model output can become a proposal — never authority.

P2 · Events start work, never prompts

Incidents begin from events. Chat can explain and request; only external events create lifecycle. Nothing in the platform wakes itself: Cloud Scheduler and Pub/Sub are the only drivers.

P3 · Cloud SQL is the only workflow authority

Agent Runtime executions, Sessions, Memory Bank, traces, model output, and connector responses are never workflow authority. Every decision reads typed rows; every prompt is rebuilt from them.

P4 · No agent invokes another agent

Agents return typed plans and results; the coordinator creates every durable agent_run and performs all dispatch. Isolation is structural, not configured, and cannot regress by editing a prompt.

P5 · Every mutation crosses the same gates

Deterministic Execution Agent → exact digest-bound authorization → target-level reservation → TOCTOU recheck → dry-run and effect comparison → receipt → independent verification. No second road exists.

P6 · Nothing verifies itself

No agent approves its own action or selects a weaker verification profile. Verification shares no identity, provider process, conversation, or mutable artifact with the producer it adjudicates. Proposer ≠ approver is enforced in code and SQL.

P7 · Identity from cryptographic claims only

Principal and scope are never taken from a header, request body, channel assertion, or model tool argument. A read-audience grant is never proof of write or steer authority. No configuration value may downgrade an identity, policy, or isolation control; absent or unparsable policy refuses.

P8 · Everything external is untrusted data

Logs, traces, repositories, tickets, tool responses, model output, and Memory Bank content are data, never instructions. Model Armor verdicts persist on evidence and gate memory promotion.

P9 · Histories are immutable

Incidents, approvals, receipts, verification results, and promoted memories are never rewritten; superseding records are added. Structured decisions and evidence references are recorded — never secrets, raw credentials, unredacted PII, or model chain-of-thought.

P10 · Sovereignty before retrieval, again before prompts

Tenant, project, environment, purpose, classification, and region filters are applied before retrieval and re-applied before prompt construction. Preview platform features carry tested degradation paths and are never the sole control on a consequential action.

Enforcement, not prose. The repository prefers deterministic enforcement in code, tests, hooks, or CI over adding prose. Where this document states a rule, the corresponding constraint lives in specs/artifacts/schema.sql, a typed service, or a named test cited in Sections 09–11.

Runtime View: Services And Planes

Twenty-three deployable applications, each a bounded, stateless Cloud Run service with its own service account and least-privilege IAM — no shared identities. Nothing is resident between steps: the platform's unit of execution is a bounded run resumed from rows.

Runtime view. Group membership is enforced by IAM, not convention: read-plane identities cannot reach mutation endpoints (SEC-IAM-READONLY-001, SEC-ACTUATOR-IAM-001), and the actuator is network-private.

Dependency rules (architecture-tested)

  1. domain imports no Solvan package.
  2. persistence depends only on domain and database libraries.
  3. Agents and delivery adapters call application; application code never imports the console or HTTP routes.
  4. Connectors cannot update incident or case state directly.
  5. Only the private Action Actuator can import mutation connectors; the Execution Agent may invoke only that actuator, with an action ID.
  6. Verification does not import remediation planning or mutation connectors.
  7. Memory promotion consumes confirmed domain events, never raw prompt text.
  8. Solvant Relay and the Action Actuator may share audited utility libraries, but neither executable may import the other's connector, route, identity, or repository boundary.

These rules are checked by the architecture-boundary stage of scripts/check; a violating import fails the merge, not a review comment.

Adoption profiles

Workload-specific topology, signals, operations, and verification journeys load as adoption profiles that never alter the domain or grant permissions implicitly. Ruhu's GCP profile (spec 11) is the first: observe-only by default, with separately gated approval-bound and bounded-autonomous phases.

Dependency direction. The red edge is deliberately unique: exactly one boundary in the system may import mutation connectors, which is what makes "no second road to production" a compile-time property rather than a review habit.

Idempotency — layered and schema-enforced

  • Alert ingress unique on (source, source_event_id); duplicates return the original durable event.
  • One active attempt per logical step (partial unique index); unique invocation_id and provider_request_id.
  • Approvals bind an exact digest with expiry; execution re-checks state, version, and policy (TOCTOU) and releases without mutating on drift.
  • Receipts unique per dispatch; undo plans derived from observed pre-state; action budgets and cooldowns bound repetition.

Data protection and sovereignty

  • Tenant/project/environment scope columns on every row; classification, purpose, and residency filters applied before retrieval and again before prompt construction.
  • Authoritative data is region-pinned to europe-west1; a placement violation is a release-blocking policy failure.
  • Tenant material under CMEK; stored long-lived credentials are read-only scoped Secret Manager references with recorded posture (target, spec 13).
  • No secrets, raw credentials, unredacted PII, or model chain-of-thought in any log, row, or trace.

Security Architecture

Identity and access

  • Distinct SPIFFE principal per agent; every Cloud Run service has its own service account with least-privilege IAM, proven by negative tests (SEC-IAM-READONLY-001, SEC-ACTUATOR-IAM-001).
  • Human identity established from verified cryptographic claims; approvals additionally require the APPROVER role, proposer ≠ approver, and an unexpired digest-bound grant.
  • Grants for reads and proposals on a person's behalf are short-lived and audience-bound, minted from verified identity — never inferred from headers, bodies, or channel assertions.

Model and content safety

  • All external content — logs, traces, repositories, tickets, tool output, model output, memory — is data, never instructions; agent prompts state it and the broker enforces it.
  • Model Armor screens supported paths inline; verdicts persist durably on evidence and gate memory promotion; a poisoned candidate is quarantined, not retried into memory.
  • Operator-facing factual claims instantiate from an enumerated, digest-pinned template registry; a failed predicate is withheld, never softened into prose.

Secrets and credentials

  • Solvan's target posture: never hold a credential capable of mutating a customer estate; mutation capability lives only in a customer-deployed actuator under customer policy, kill switch, and rate budget (spec 13).
  • Every stored credential records its posture; federated short-lived credentials preferred; stored long-lived keys are read-only scoped Secret Manager references under per-tenant CMEK, surfaced in the console.
  • Development and key-file hosts are never production-eligible by default.

Fail-closed configuration

  • No configuration value may downgrade an identity, policy, or isolation control to a permissive mode; absent or unparsable policy refuses.
  • The Agent Gateway is registry-governed and fail-closed with no generic mutation route; bypass denial is a deployed test (SEC-GATEWAY-BYPASS-001) re-proven by deployment preflight (gateway_bypass_denied).
  • Preview platform features carry tested degradation paths and are never the sole control protecting a consequential action.

Both paths are chains of independent gates with no shared discretion: the components that propose, approve, execute, and verify are different identities with different IAM, and the review-time threat model (stale attempts, duplicate delivery, cross-incident target races, restart recovery, memory poisoning, cross-tenant access) has a named test per row in Section 10.

Reliability And Continuity

Solvan's continuity model is structural: there is no long-lived process whose loss can lose work. Suspension is a database state; recovery is a fresh, fenced attempt rebuilt from rows; repeated effects are impossible by constraint rather than unlikely by care.

Continuity of multi-week work

Reliability Cases (15 states) and scheduled_wakeups carry work across days with zero resident compute: an 18-hour approval pause or a 7-day case survives any deployment or crash because it is rows, not a parked invocation. Workspace continuity uses hibernated checkpoints rehydrated under exact provider revision and boot-proof validation.

What is deliberately not promised

No mid-invocation resume: a half-finished model invocation is never trustworthy state and is always discarded in favor of a fresh fenced attempt. Upstream exactly-once is never claimed without a separately qualified provider idempotency contract; Solvan's own exactly-once claims are per-dispatch receipts and schema constraints, and stop at its boundary.

Observability And Operations

Telemetry model

  • OpenTelemetry across every service; spans exported to Cloud Trace and joined to the domain timeline via trace_id/span_id columns on runs — a judge or operator can walk from an incident row to the exact trace and back.
  • Structured decision records with reason codes and budget states; stop reasons are recorded, chain-of-thought never is.
  • Every tool call, cache hit included, is one tool_calls row with fingerprint and receipt.

Operator surfaces

  • Console: incidents, cases, fleet, approvals (target, digest, environment, risk, expiry), evidence (source, freshness, classification, armor verdict), release evidence — control made visible.
  • Validated versus inferred findings are visually and semantically distinct; an unresolvable citation renders inert and demotes the statement to inferred.
  • Local parity: scripts/observe [status|logs|traces] inspects any worktree's isolated stack.

Operational guidance

  • Runbooks and skills live as governed data with registered completion predicates (specs 17–18): guidance versions are approved, pinned, and evaluated — never free prose a model can drift. Implemented and locally verified.
  • Autonomy is an earned, revocable receipt derived from outcome quality, not a configuration default (spec 20).

Alert operations

  • Canonical event ingress normalizes Cloud Monitoring webhooks and detector bursts into idempotent durable events; alert triage (spec 21) runs on the same fenced-claim machinery as everything else.
  • Nothing pages a human by default: escalation is a policy outcome with a durable record, and abandoned work escalates via the stale-progress policy.
Auditability as a feature. Because histories are append-only and superseded rather than rewritten, the answer to "who decided what, on which evidence, under which authority" is a query, not an investigation.

Implementation Status And Roadmap

The honest claim, in three levels. The release-gated slice runs under enterprise controls and is the only basis of any release claim. A second tier is implemented and locally verified in this same codebase, with cloud release qualification deliberately pending. The remainder is specified: reviewed normative contracts with acceptance tests, not roadmap prose. Solvan continues beyond the competition as Ruhu Inc.'s production reliability platform.

Release-gated — the demonstrated slice

  • Event-driven incident lifecycle with durable coordination, recovery, quarantine, and multi-day cases.
  • Bounded agent fleet on Agent Runtime with typed contracts and structural isolation.
  • Action safety path: exact approvals, reservations, TOCTOU rechecks, dry-run, receipts, independent verification.
  • Governance plane: per-agent SPIFFE identity, fail-closed Gateway with tested bypass denial, Model Armor verdicts, Registry-driven routing.
  • Data authority model: 61-table release schema, evidence objects, gated Memory Bank.
  • Region-pinned dual-project deployment with preflight-gated releases.
  • Ten-stage merge gate with PR-001..050 traceability (953 tests).

Implemented — locally verified, qualification pending

  • Conversational surface (spec 14): five channel liaisons on one ledger — Slack lifecycle, steer confirmation, subscriptions, deterministic compaction.
  • Governed Tool Catalog (16) and Operational Guidance (17): hash-bound selection and computed completion in real coordinator dispatch.
  • Agent Skills interchange (18): quarantined import; local implementation gate passed.
  • Alert triage (21): 28-table schema, fenced-claim runtime, console surfaces.
  • Production environment model (20): production graph and earned-autonomy receipts substantially implemented.
  • None of this tier is part of any release claim until cloud qualification runs with valid authority.

Specified — target contracts

  • Solvant Relay (spec 22): customer-resident read-only evidence collection; specification complete, implementation early.
  • Customer-deployed actuator (spec 13): Solvan never holds an estate-mutating credential.

  • Ruhu adoption profile (spec 11): observe-only → approval-bound → bounded autonomy, receipt-gated phases.

CAS transitionCompare-and-set state change bound to expected state and workflow version; the only way workflow state moves.
TOCTOU recheckRe-validation of state, versions, epoch, and policy at execution time; any drift releases the reservation without mutating.
ReceiptThe unique-per-dispatch durable record of an actuation, dual-written to a customer-owned sink.
Evidence objectA hash-addressed GCS artifact with classification, residency, freshness, retrieval actor, and armor verdict.
Promotion gateThe rule set (type-specific confirmation + recorded armor verdict) between confirmed events and Memory Bank.
LiaisonA channel worker (Slack, email, Discord, MCP, console) reading reader-filtered projections of one conversation ledger.
WorkspaceA logical Cloud SQL/GCS record executed through bounded stateless provider tasks; no provider process or filesystem is durable state.
SandboxThe separate no-egress Cloud Run service that produces patch/test truth; the only source of "tests passed."
ActuatorThe single private service allowed to import mutation connectors and touch production, by stored action ID only.
VerifierThe independent service computing recovery verdicts from fresh telemetry and synthetic probes; shares nothing with producers.
CellThe placement and capacity boundary holding one tenant population's runtime and data (spec 19; target).
Placement grantThe signed decision binding an organization to its one writable home cell and epoch.
Adoption profileA workload-specific contract (signals, topology, journeys) that never alters the domain or grants permissions implicitly.
